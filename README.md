# Amp
Client modification for popular MMO game ROBLOX to allow unsigned lua script execution via the ingame VM.

# What is this?
Amp is an old out-dated tool that allowed for end-users to create, edit and execute lua scripts within the ROBLOX lua environment. Typically this is protected and only allows signed scripts to execute in its environment. Amp allows for unrestricted and unsigned access to the ROBLOX lua API and execution within it taking advantage of prevalent flaws within the environments sandbox.

# How does it work?

Understanding Roblox's Lua environment and how signed function prototypes are run in its virtual machine (VM) is a prerequisite for comprehending how Amp functions.

Lua-u, Roblox's proprietary Lua implementation, is available as open-source software on GitHub. Developing a processor (or "transpiler") that can transform standard Lua 5.1 function prototypes into a Roblox-compatible format is the first significant challenge. The client/Transpiler.cpp file handles this process, which entails mapping standard Lua 5.1 VM instructions to their Roblox counterparts. Reverse-engineering the Roblox VM's opcodes and register usage is necessary to accomplish this. After being comprehended, the standard Lua instructions are repositioned, mapped, and saved in a format that works with Roblox.

The Roblox deserializer is the second step. During game initialisation, Roblox typically receives signed bytecode from the server, deserialises it into a function prototype, and then pushes it onto the Lua stack to run. This procedure is re-implemented in reverse by Amp, which takes the prototype of the remapped function, turns it into bytecode that is compatible with Roblox, and signs it in a manner that Roblox accepts.

Finally, just like a real server-provided script, this freshly created bytecode is fed into the Roblox deserializer. After that, the function prototype is moved to the Lua stack, where it is prepared for execution.

To put it briefly, Amp functions by copying Roblox's bytecode format, transforming user-generated bytecode into it, and then feeding it into the engine to run it as though it were sent straight from the Roblox server.
